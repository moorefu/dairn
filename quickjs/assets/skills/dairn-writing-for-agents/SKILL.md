# Dairn Writing for Agents

面向 Agent 的文档不是给人看的说明，而是**每次运行都会被执行的指令**。目标是让同一条指令稳定地产生同一行为。

## 两种负载

- **上下文负载**：常驻 Agent 窗口的内容（AGENTS.md 的每一行、Skill 的 description）每轮都花 token 和注意力，只保留触发与约束。
- **认知负载**：人需要记住“有哪些文档、何时用哪份”。它不是要清零的成本，而是人保留控制权的代价；把判断权交给人的地方就该花这份成本。

被指针引用的深层文档只付指针那一行的代价；没有任何指针的文档，全靠人的认知负载发现。

## 信息层级与渐进披露

按“多快需要”排序：

1. **步骤**：Agent 现在要按顺序执行的动作，放主文件。
2. **参考**：需要时查的规则、字段、示例，可与步骤同文件。
3. **披露参考**：只有部分分支才会用到的细节，移到独立文件，由指针按条件触达。

判断标准是分支：每个分支都要用的留在主文件，只有部分分支用的推向指针。主文件膨胀时先披露参考，再按序列拆分；拆分跨越真实的上下文边界（新会话、subagent）才有效。

## 写法

- **领先词**：用模型已有先验的紧凑术语承载一类判断（seam、tracer bullet、frontier、tight loop）。首次给出定义，之后重复 token 而不是重复整句。
- **正向指令**：写“做什么”，不写“不要做什么”。否定会激活被禁概念；只有在无法正向表达的硬护栏处才保留禁令，并紧跟正向目标。
- **可检查的完成判据**：每条步骤以“怎么算做完”结束，优先写成可观察条件（命令退出码、文件字段、未决问题清零）。判据模糊会让 Agent 提前宣称完成。
- **单一事实来源**：同一含义只写一处，其他位置用链接或指针；复制两份必然漂移。
- **去掉 no-op**：不改变默认行为的句子直接删，不要只删几个词。
- **链接而非复制**：引用命令、字段、示例时指向权威 Spec 或 `--help` 输出，避免缓存过期。
- **行数预算**：AGENTS.md 目标不超过 100 行；单个 SKILL.md 目标不超过 80 行并只覆盖一个阶段；超出就披露参考或明确不做。
- **frontmatter 触发描述**：把触发场景写在 description 前部，1-2 句，不超过 1024 字符；模型可调用的 Skill 保留“何时使用”的触发语，只允许人调用的 Skill 写成人类可读摘要。

## 落点

- `AGENTS.md`：导航指针、不可违背的边界、入口命令；不复制项目指南正文。
- `.agents/skills/**/SKILL.md`：一个阶段一套步骤、证据记录方式、失败语义。
- `docs/specs/`：可被稳定 ID 引用的权威契约；Skill 只写执行步骤，不重述契约。
- `docs/PROJECT_GUIDE.md`：项目事实与实测结论，不得写入未验证推断。

## 校验

- `dairn docs check`：资产元数据、稳定 ID、相对链接与 CLI 命令一致性。
- `dairn validate`：项目结构与治理配置校验。
- 两个命令都只做结构校验；文档里的“已通过”结论仍要来自真实执行与人工审查。

## 失败模式

- **沉淀**：只加不删的过期层，越读越找不到现行规则。改行为时同时回收旧表述。
- **重复**：同一含义多份副本，改一处忘一处。
- **否定堆叠**：满是禁止句的文档把注意力引向被禁行为。
- **无判据步骤**：没有完成条件的步骤会让 Agent 用“看起来做完了”代替验证。
