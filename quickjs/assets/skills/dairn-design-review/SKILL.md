# Durable Design Review

## 何时激活

鉴权、权限、资金、序列化格式、网关网络协议、多模块 API、数据库迁移、并发状态、超时重试、资源生命期、性能架构调整及其他 L2 变更。

## 评审过程

1. 读取现行接口、调用方和既有 Agent Notes，辨认有无重复/已被取代的决策。
2. 明确前置条件、状态转换、异常/取消路径、部分成功和未知结果、资源清理责任。
3. 真实比较至少一个候选方案；若没有合理替代项，说明原因，不杜撰备选以凑格式。
4. 明确性能上限与错误预算、兼容性与迁移、安全威胁、测试不变量和回滚边界。
5. 仅当存在长期有效的设计决策理由，才在 `.agents/notes/proposed/<category>/YYYY-MM-DD-topic.md` 创建 Note，遵循 `proposed-note.md`；其余 L2 审查结论由 PR/MR 承载，不制造无意义的 Note。
6. 交付后移至 `implemented/`，正文变成已实施的事实；拒绝的提案放 `rejected/` 并陈述原因。
7. 将人工架构/安全批准在真实 PR review 中落实；**Agent 输出的“同意”不是批准**。

**阻断条件**：未定义失败后的状态、不可验证的验收、与现行接口不兼容却缺少迁移、无 Owner 的跨模块协议、未获必要人工批准。
